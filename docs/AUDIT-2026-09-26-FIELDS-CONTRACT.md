# Audit 2026-09-26 — FIELD_CATALOG vs backend response contract

Scope: every entry of `FIELD_CATALOG` in `web/src/lib/fields.ts`, checked against the
backend that serves it (SQL alias in `src/api/handlers/analytics.ts`, the row interface
in `src/api/types.ts` the handler is typed to, and the underlying view or loader where
units matter). Unit and source claims were checked against the live DB with read-only
SELECTs on 2026-09-27.

Status values: **match** (key, label and units agree) · **renamed** (catalog column
differs from the backend SQL column but maps to the right JSON key) · **missing-in-backend**
(catalog entry with no serving column) · **missing-in-catalog** (backend column no field
reads) · **unit/label mismatch** (key is right, the text described a different quantity).

Result: **no key drift**. Every catalog column is a key of its endpoint's row interface,
and every `ENDPOINTS[*].rowsKey` is that endpoint's row array. 11 entries had label or unit
text that did not describe what the backend computes. Those are fixed in `fields.ts` in
this change. `web/src/lib/fields.test.ts` ("backend contract") now parses
`src/api/types.ts`, so a later rename on either side fails the test.

## Backend columns no catalog field reads (missing-in-catalog)

These are reported only; no fields were added.

- municipios: `cve_mun`, `farmacias`
- top-sectors: `scian`
- risk-summary: `cve_mun`, `robo_negocio`, `extorsion`, `patrimoniales`, `violentos`, `total_baseline`, `delitos_per_1k_pop`, `delitos_change_pct`
- mortality-summary: `cve_mun`, `def_menores_1ano`, `def_endocrinas`, `def_externas`, `tasa_mortalidad_per_1k`, `tasa_infantil_per_1k`
- locust-muni: `cve_mun`, `pea`, `denue_farmacias`
- locust-estado: `cve_ent`
- locust-ageb: `cvegeo`
- national-treemap: `entidad`

**Finding #62 (`tasa_infantil_per_1k`).** No web surface shows this field: no catalog entry, no
zod schema, and no string in `web/src`. There is no web label to align. P19 corrected the
backend doc to "defunciones <1 año por 1k hab.". If a catalog entry is ever added, it must use
that label and must not say "mortalidad infantil".

## Out of scope, same bug class (not changed here)

`web/src/lib/map-layers.ts` (map layers served by `src/api/handlers/layers-values.ts`)
repeats three of the mislabels fixed above:

- `dm2_casos_promedio` says "SUS".
- `monto_credito_comercial` says "crédito comercial".
- `monto_subsidiado_vivienda` says "Subsidio vivienda" / "Monto subsidiado".

The layer ids are backend keys and must stay. Only the label and description strings need a
follow-up.
