## Proposal

Tables `mun_polygons_2025`, `ageb_polygons_2025` (optionally
`ent_polygons_2025`, `loc_polygons_2025`). Never `-overwrite`/`-append` on
the 2020 names.

```
ogr2ogr -f PGDUMP /vsistdout/ \
  "/vsizip//vsizip/raw/mg2025/794551163061_s.zip/mg_2025_integrado.zip/conjunto_de_datos/00mun.shp" \
  -nln mun_polygons_2025 -lco SCHEMA=public -lco GEOMETRY_NAME=geom -lco FID=ogc_fid \
  -lco SPATIAL_INDEX=GIST -lco CREATE_SCHEMA=OFF -lco DROP_TABLE=OFF \
  -nlt PROMOTE_TO_MULTI -t_srs EPSG:4326 \
| docker exec -i supabase-db psql -U postgres -d postgres -v ON_ERROR_STOP=1 --single-transaction
```

## Loader (2026-09-29, not run live yet)

`scripts/load-mg2025-polygons.ts` implements the proposal above. It is the
source of truth for the two tables; `scripts/migrations/028-mg2025-polygons-grants.sql`
carries only its owner / REVOKE / GRANT / COMMENT lines (pinned by
`scripts/load-mg2025-polygons.test.ts`) so a grants audit can re-apply them.

- **Stream**: `ogr2ogr --config PG_USE_COPY YES -f PGDUMP /vsistdout/` per
  layer, straight out of the nested zip, split into lines in Node and piped
  into ONE `docker exec -i supabase-db psql -X -v ON_ERROR_STOP=1 -f -`
  (peak RSS 142 MB for both layers; the AGEB dump is 424 MB of SQL, the
  municipio dump 122 MB). The filter drops the dump's own `BEGIN;`/`COMMIT;`,
  refuses any `DROP`/`TRUNCATE`/`DELETE` and any statement not naming the
  target table, and checks one COPY block with the expected row count.
- **Transaction**: an explicit `BEGIN;` at the top and `COMMIT;` as the very
  last line, written only after every layer streamed cleanly. Not
  `--single-transaction`: with `-1`, psql commits whatever it read when its
  stdin ends, so a loader killed mid-stream would commit a truncated table
  (proved on a throwaway: a cut COPY under `-1` committed 2 rows, exit 0;
  without the COMMIT line the table does not exist). A SIGKILL of the loader
  mid-COPY under `--force` left the previous table intact (DROP rolled back).
- **Post-steps, same transaction**: invalid count NOTICE, the 019:268
  `ST_MakeValid` repair, `<t>_cvegeo_uq`, `idx_ageb_polygons_2025_ent_mun`,
  `ANALYZE`, owner postgres, REVOKE anon/authenticated/trustr_app on the
  table and its `_ogc_fid_seq`, REVOKE denue_sage, GRANT SELECT denue_api,
  `COMMENT ON TABLE` (MG 2025, UPC, zip sha256), then a DO-block assertion:
  mun 2,478 rows = 2,478 keys, 0 NULL, only non-empty MULTIPOLYGON, SRID 4326,
  0 invalid, `Find_SRID` 4326, `EXCEPT mun_polygons` = exactly
  `02007 04013 12082 12083 12084 12085 24059 25019 25020`, reverse 0,
  `04013 = Dzitbalché` and `12083 = Ñuu Savi`; AGEB 82,283 / 82,283 / 0 with
  Urbana/13-char 64,808 and Rural/9-char 17,475. Any failure rolls back.
- **Guards**: the zip's sha256 is checked first; an existing target table
  makes the loader exit before psql unless `--force` (then `DROP TABLE IF
  EXISTS` without CASCADE inside the transaction); `SET LOCAL
  statement_timeout 30min`, `lock_timeout 10s`, no parallel workers. The
  stream filter accepts, outside the COPY data, only one statement per line
  ending in its `;`, and only the shapes the dump produces (`CREATE TABLE`,
  `ALTER TABLE`, `SELECT AddGeometryColumn`, `COMMENT ON TABLE`, `COPY`,
  `CREATE INDEX`, the exact `SET standard_conforming_strings = ON;`).
- **`--force` reload = street-geometry outage.** The `DROP` at the top of the
  transaction holds ACCESS EXCLUSIVE on `mun_polygons_2025` until COMMIT.
  Once `osmium.ts` reads that table, every `/analytics/street-geometry` bbox
  lookup blocks for the whole load window (~1–1.5 min) and fails at
  psql-runner's 25 s statement_timeout. Run a `--force` reload in a quiet
  window. (Not a concern for the first load: the table does not exist yet.)
- **No `service_role` grant, on purpose.** The 2020 polygon tables still
  carry `service_role=arwdDxt` (a leftover of the supabase_admin default ACL);
  the 2025 tables are created by `postgres`, whose live default ACL grants
  only `trustr_app` (revoked). Nothing reads polygons through PostgREST, so
  this is not a parity bug.
- **Encoding**: the shapefile driver honours `.cpg` 88591 and emits UTF-8
  (`Dzitbalch\xc3\xa9`); no `SHAPE_ENCODING` override is needed. The dry run
  and the live filter both look for the two names in the COPY rows.
- **Throwaway proof** (`supabase/postgres:15.8.1.085`, `-m 768m`, stub
  `mun_polygons` = the 2025 keys minus the 9): mun 2,478 rows in 28 s, peak
  149 MiB; AGEB 82,283 rows in 46 s, peak 231 MiB; 0 invalid geometries
  before repair in both layers (the 2020 AGEB layer had 22); tables 64 MB +
  246 MB. The assertion fails as designed on a deleted 2025 row, a
  stub key removed (EXCEPT = 10 keys), a 2020 key missing from 2025, a
  mangled name and an invalid geometry.

and the "next:" hints of `load-censo.ts` / `load-cofepris.ts`. After the merge
and before the restart, re-run `api-role.sql` from `main` (or migration 028)
so the grant is proven on `main`'s copy.
